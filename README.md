# RTP 双线路合流网关

演播室两条线路送同一路 RTP 视频（同一 SSRC），解码器只接一路。本网关从两个
UDP 端口收包，按 RTP 序号去重保序后，从首包起把原始报文按序送到唯一 UDP 出口。

## 合流规则

1. **首包定起点**：第一个到达的包决定起始序号与 SSRC，从它开始按序原样转发；
2. **半周期窗口**：来包序号与待发位置相差不到半个序号周期（32768）才接受，
   否则按迟到/重复丢弃 —— 跨 65535 回绕同样成立，同一原包最多发一次；
3. **任一路补齐**：乱序包进缓存等缺号，哪一路先送到就用哪一路；
4. **50ms 放行上限**：每个待发包从首次收到起最多等 50ms，超时跳到该包按序
   发出，途中缺号跳过；
5. **128 缓存上限**：待发包达到 128 个时，立即跳到最靠前的包继续发；
6. **迟到即弃**：缺号被跳过后才到的包直接丢弃。

## 启动

```bash
docker compose up --build
```

或本地运行（Python 3.11+）：

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 端口与配置

| 用途 | 默认 | 环境变量 |
|---|---|---|
| HTTP / Swagger UI | 8000/tcp | — |
| 线路 1 收包 | 5004/udp | `LINE1_PORT` |
| 线路 2 收包 | 5006/udp | `LINE2_PORT` |
| UDP 出口（解码器） | 127.0.0.1:6000 | `OUTPUT_HOST` / `OUTPUT_PORT` |
| 出口监视器 | 6000/udp | `MONITOR_PORT` |
| 待发包等待上限 | 50ms | `TIMEOUT_MS` |
| 待发包缓存上限 | 128 | `BUFFER_MAX` |

默认出口指向容器内置监视器（127.0.0.1:6000），便于直接查看实收序号；
接真实解码器时把 `OUTPUT_HOST`/`OUTPUT_PORT` 指向解码器即可。

## Swagger 自测

打开 `http://localhost:8000/docs`：

- **POST /inject**：按线路（`line` 1/2）、序号（`seq`）、延时（`delay_ms`）
  投送样包；`count` 连发多个递增序号，`interval_ms` 控制多包间隔；
- **GET /received**：UDP 出口实收序号列表，`t_ms` 为相对首个实收包的毫秒数；
- **GET /stats**：合流器状态（待发位置、缓存、各类丢弃/跳转计数）；
- **POST /reset**：清空合流状态与监视记录（并取消未执行的延时投包）。

示例：线路 1 发 1000、1001、1003、1004，线路 2 补 1002，然后看
`/received` 得到有序的 1000–1004。

## 自动化自测

```bash
python3 tests/test_merger.py          # 合流核心单元测试（假时钟，无需网络）
python3 scripts/e2e_test.py           # 端到端：投包 -> 校验出口实收（需先启动网关）
```

端到端覆盖：补包、重复去重、65535 回绕、50ms 超时放行、128 缓存上限放行、
缺号跳过后迟到包丢弃。

## 目录

```
app/merger.py   合流核心（纯逻辑，无 I/O）
app/main.py     FastAPI：UDP 收发、出口监视器、HTTP 接口
tests/          单元测试
scripts/        端到端自测脚本
```

## 已知限制

- 首包学习 SSRC，之后异 SSRC 的包丢弃并计数（`ssrc_dropped`）；改源需 `/reset`；
- 半周期窗口（32768）是 RTP 序号去重的常规取舍，超前半个周期以上的包会被
  当作迟到包丢弃；
- 出口监视器与网关同进程，仅用于演示与自测，不是线速探针；
- 超时巡检周期 1ms，50ms 上限的实际放行误差为毫秒级。
